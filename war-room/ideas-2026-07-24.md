## Ideas (13, ranked)

### 1. Regret Ledger: every veto emits a shadow fill; cockpit surfaces net R saved vs c
*high feasibility* — argued by: Brainstormer, Architect, Auditor, User Advocate

Every vetoed setup writes a phantom trade to a shadow-fill table using execsim.py's existing fill machinery. Nightly job computes counterfactual R per veto class. Cockpit card: 'ATR veto: -2.1R cost / +8.3R saved / net +6.2R — keep' with a one-click 'relax 20%' button. Vetoes stay auditable; Mom sees the tradeoff, not the rule. Sizing-instead-of-vetoing (User Advocate's pressure) is also addressable here: relax a veto by reducing size to 0.25R rather than binary reject.
- **Why it's non-obvious:** Turns risk from cost-of-action tracking into cost-of-inaction tracking, and dissolves User Advocate's opacity objection to Contrarian's veto stack. Self-modifying risk is explicitly rejected; human-in-loop is the load-bearing safety property.
- **Grounding:** execsim.py already simulates fills — shadow table is the same schema with is_phantom flag. Plugs into telemetry.py and runlog.py without new tables beyond the shadow log itself.
- **Builds on:** contrarian-defense-stack-first, brainstormer-regret-ledger

### 2. Strict role separation: HTF permits direction, LTF triggers entry, Cycle scales 
*medium feasibility* — argued by: Brainstormer, Architect, Auditor, User Advocate

Strict three-layer role separation: HTF structure emits a permission-slip fact (long-only / short-only / both / neither); LTF setups only fire inside that permission; cycle phase (early/mid/late) multiplies approved size (1.5x / 1.0x / 0.5x). Three layers, three jobs, zero overlap — kills 'which module wins' ambiguity without a committee-of-experts auction or branching logic inside setups.py.
- **Why it's non-obvious:** Breaks my own round-1 committee-of-experts auction idea. Competition between modules is the wrong metaphor; strict role separation is the right one. Also breaks the common retail pattern of treating HTF/LTF/cycle as three independent signal sources that get averaged.
- **Grounding:** regime.py already emits directional facts with evidence payloads. cycles.py exists (observational per README — promotion is the lift). setups.py regime_at() inline lookup is replaced by permission-slip fact query.
- **Builds on:** brainstormer-htf-permits-ltf-triggers-cy, brainstormer-htf-permits-ltf-triggers

- **Grounding:** setups.py:39 FORMING_TFS already implemented; risk.py sizing math already exists. Just move the compute earlier in the state machine.

### 7. Convert soft vetoes into size-attenuators; keep hard vetoes for structural death
*high feasibility* — argued by: Brainstormer

Two-tier defense: HARD vetoes (HTF structural break, correlation kill-switch, liquidity drought) still reject. SOFT conditions (ATR at 150% of mean, mid-cycle exhaustion, thin session) become size multipliers — 0.25R instead of 1.0R. Mom gets the occasional upside on borderline setups without the calcification User Advocate warned about.
- **Why it's non-obvious:** Breaks the binary framing of Contrarian's veto stack. Not every defensive signal deserves a full reject — some deserve a whisper. Regret Ledger becomes the arbiter of which tier a given condition belongs in.
- **Grounding:** risk.py already computes size multipliers. This adds a soft-attenuator table alongside the veto table; both consult regime.py facts.
- **Builds on:** contrarian-defense-stack-first, user-advocate-size-not-veto

### 8. Survival-sizing per trade + portfolio-heat governor across open book
*high feasibility* — argued by: Architect

Replace edge-based sizing (Thompson/Kelly) with survival math: max-tolerable-losing-streak sets per-trade R so the daily-loss kill switch survives N consecutive losses. Add a portfolio-heat governor to risk.py that sums open R weighted by pairwise correlation, capped at 3R total book heat. Volatility regime scales the cap (COMPRESSION = full, EXPANSION = half, DISORDERED = quarter).
- **Why it's non-obvious:** Breaks the assumption that per-trade sizing is sufficient. Correlated crypto drawdowns nuke accounts regardless of per-trade discipline; the governor is the difference between paper-trade darling and something Mom can leave running.
- **Grounding:** risk.py already owns the sizing authority per §9. Consumes the volatility fact from idea #1. Pairwise correlation is cheap on the existing universe candle store.
- **Builds on:** contrarian-sizing-by-survival

### 9. BTC intraday ±3% correlation kill-switch for alt setups — one SQL query
*high feasibility* — argued by: Auditor

If BTC moves ±3% on the current daily candle, veto all non-BTC/ETH setup emissions. Alt market structure during a BTC shock is noise, not signal; zones do not hold. BTC-USD candles are always in the store as a SEED pair — the check is one SELECT against the current day's open/close before playbook() fires.
- **Why it's non-obvious:** Cheapest defensible veto in the room: ~10 lines in setups.py, zero new data, zero new infrastructure. The data is present and unused for this purpose today.
- **Grounding:** universe.py SEED = ('BTC-USD', 'ETH-USD') guarantees BTC candles always exist. setups.py playbook() has zero correlation awareness today.
- **Builds on:** contrarian-defense-stack-first

### 10. Session-aware gates: maker-only mean-revert in Asia, breakout entries in London/
*high feasibility* — argued by: Auditor

Crypto liquidity is session-structured: Asia session is thin (maker fills cleanly, momentum weak); London/NY overlap is fat (momentum follows through, taker fill acceptable). market_time is already on every setup fact. Gate mean-revert entries to Asian session for fee rebate; gate compression-breakouts to London/NY open for follow-through. Zero new data — a UTC timestamp range lookup in playbook().
- **Why it's non-obvious:** No seat named time-of-day. The timestamp is on every emitted fact; nobody is using it to filter. This captures a known structural edge in crypto intraday liquidity for ~20 lines.
- **Grounding:** setups.py stores market_time on every fact; playbook() has no session awareness. Fisherman/Surfer personalities (once volatility-fact-unblock ships) are the natural consumers.
- **Builds on:** architect-personality-swap

### 11. Cockpit as weather report, not trade log — surface conditions and Regret Ledger 
*medium feasibility* — argued by: Brainstormer

Front page shows: trend strength, volatility band, liquidity depth, bot posture, expected setups today. Single narrative line: 'Yesterday we caught 1 of 3 setups; the two we skipped both hit stops. Vetoes saved you $47.' Mom sees the sky, not the ticker.
- **Why it's non-obvious:** Breaks the assumption that the cockpit shows what happened. It shows what's coming and what the bot's stance is toward it. Explainability becomes a rendering problem — game engines solved this with minimaps and threat indicators years ago.
- **Grounding:** server.py + static/index.html already exist as the UI seam. Requires new aggregator endpoints exposing regime/liquidity/regret-ledger totals — no engine changes.
- **Builds on:** user-advocate-mom-is-north-star

### 12. Confidence Contract: bot pre-declares expected hold, drawdown, TP1 probability p
*medium feasibility* — argued by: Architect

Every trade writes three numbers to the trade record BEFORE opening: expected hold-time bars, worst-case position drawdown %, and TP1 probability from the last 50 same-class trades. Post-mortem compares declared vs actual. Monthly Mom-language report: 'Fisherman declared 68% TP1; actual 71%. Declared max 2.1% DD; actual worst 2.4% — within tolerance.' Auto-pause any playbook whose declared-vs-actual diverges beyond 2σ.
- **Why it's non-obvious:** Translates the constitution's 'no mystery score' requirement into a Mom-legible trust contract. Creates a natural, deterministic kill-switch that doesn't require the operator to interpret regime math — the bot polices itself against its own prior claims.
- **Grounding:** telemetry.py and runlog.py already record per-trade metadata. The 50-trade rolling class stats can be computed from the existing execsim results table.
- **Builds on:** architect-confidence-contract

### 13. Cockpit veto toggles: BTC kill-switch, ATR gate, correlation sensitivity
*medium feasibility* — argued by: User Advocate

Surface key veto parameters as cockpit dials (BTC correlation: ON/OFF, ATR sensitivity: tight/medium/loose). Mom tunes risk tolerance without code. One-click adjustments, no mystery.
- **Why it's non-obvious:** Breaks the assumption that vetoes are hard rules. Makes them tunable, giving operator agency while keeping veto stack intact.
- **Grounding:** Follows from regret-ledger (once Mom sees veto trade-offs, she wants to tune). UI already surfaces risk params; veto toggles are the same pattern.
- **Builds on:** regret-ledger-shadow-fills
