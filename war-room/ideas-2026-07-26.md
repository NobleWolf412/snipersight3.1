## Ideas (15, ranked)

### 1. Persistent cockpit health strip showing degraded/disabled setup types
*medium feasibility* — argued by: Brainstormer, Architect, Auditor, User Advocate

One system-level status line in the cockpit frame that reads e.g. 'zones: DEGRADED (auto-disabled 09:42, 3 divergences) — ingest: OK'. Fed directly from the current Kill-Switch rung per stage. No per-signal badge (cert-warning blindness), no invisible silence (operator assumes quiet market).
- **Why it's non-obvious:** Breaks the false choice between User Advocate's Trust Meter (badge fatigue) and Contrarian's pure silence (invisible degradation). Moves trust signal out of the signal path and into the frame — impossible to miss because the whole strip changes colour.
- **Grounding:** cockpit UI already exists at app/static/; /api/status endpoint already exists in server.py as the ping target; audit rung state from kill-switch-ladder-dispatch provides the data feed.
- **Builds on:** architect-health-strip, advocate-trust-meter, trust-meter, kill-switch-ladder-dispatch, engine-health-strip, kill-switch-ladder

### 2. Watchdog calls quality.audit() and restarts live on STALE_SERIES climb
*high feasibility* — argued by: Brainstormer, Auditor, User Advocate

~10 lines in watchdog.py:main() — invoke quality.audit() on a timer, diff STALE_SERIES count against prior cycle, toast + restart live.py when it climbs. Converts the existing 'is the process breathing?' check into 'is the process working?' without any new infrastructure.
- **Why it's non-obvious:** Breaks the assumption that diagnosis infrastructure needs to be built — audit() already produces the exact STALE_SERIES finding and is simply never called from the watchdog. The wound and the cure are already in the tree.
- **Grounding:** quality.audit() returns STALE_SERIES findings directly; watchdog.py:server_up() only pings /api/status and cannot detect a live scanner that stopped ingesting; toast() and log() infra already present in watchdog.py.
- **Builds on:** auditor-watchdog-audit-call

### 3. Two-tier expo: hard reject on contract violations, soft quarantine on outliers
*medium feasibility* — argued by: Brainstormer, Auditor, User Advocate

Split the expo gate: contract violations (negative volume, timestamp inversion, schema break) raise and halt — those are bugs. Statistical outliers (>Nσ ATR) quarantine and keep serving — halting on a flash crash bar is worse than the disease. Resolves the Contrarian/Architect freeze debate without either losing.
- **Why it's non-obvious:** Breaks the false binary of 'freeze vs pass-through'. Halting on a flash-crash bar is worse than the disease; halting on a schema break is mandatory. Different failures deserve different verdicts.
- **Grounding:** quality.py:audit_market_inputs() already distinguishes BLOCKED (OHLC_INVARIANT_FAILURE) from DEGRADED (STALE_SERIES); the two-tier split is a formalization of a distinction the code already implicitly makes.
- **Builds on:** contrarian-fail-loud, architect-expo-home, two-tier-expo

### 4. Five-rung Kill-Switch Ladder as the single vocabulary for degradation
*high feasibility* — argued by: Architect, User Advocate

Every assertion in quality.py declares which rung it triggers: Serve, Serve+flag, Quarantine, Auto-disable, Halt. A rung column in frame_log (or the existing runlog) turns 'what is the engine doing right now?' into one SQL query. Replaces today's ad-hoc mix of log/raise/silent-drop with a shared five-state language the watchdog, cockpit, and audit trail all speak.
- **Why it's non-obvious:** Breaks the healthy-or-halt binary that Contrarian and I were fighting over. The architecture stops needing to guess which failure mode is live — drift fills rungs 2-4, cardiac fills rung 5, one vocabulary handles both.
- **Grounding:** quality.py already produces categorized diagnoses (STALE_SERIES, KNOWN_VENUE_GAPS, NO_ELIGIBLE_PLAYBOOK); rungs are just a schema over what audit() already returns. No new engines, one enum + one column.
- **Builds on:** two-tier-expo, watchdog-calls-audit

### 6. Split diagnostics into two clocks: cardiac (watchdog) vs rot (telemetry)
*high feasibility* — argued by: Brainstormer

Stop mushing discrete failures and continuous drift into one diagnostics surface. Watchdog owns loud/discrete (STALE_SERIES, contract violations, process health). Telemetry owns quiet/continuous (distributional drift, divergence trends). Every future diagnostic gets categorized into exactly one clock.
- **Why it's non-obvious:** Breaks the implicit assumption that 'diagnostics' is one concern. Different failure timescales need different alarm shapes; one dashboard for both trains the operator to trust neither.
- **Grounding:** diagnostics.py currently mixes both; Auditor confirmed the 59 STALE_SERIES are discrete/ingest-side, not drift — proving the two clocks are already tangled in the current diagnosis.

### 7. Minimal frame_log as the postmortem trail for watchdog restarts
*high feasibility* — argued by: Brainstormer

After watchdog auto-restarts live, the operator's next question is 'did we miss setups, is recovery clean?' A minimal frame_log(ts_close, symbol, stage, input_hash, output_hash) answers that in one query. Not for pre-dawn surveillance — for the 09:00 postmortem.
- **Why it's non-obvious:** Breaks the 'observability must be real-time' assumption. Repositions frame_log from live monitoring to forensic replay for a specific, high-value question that arises AFTER auto-recovery.
- **Grounding:** SQLite WAL already present; runlog.py exists. Complements watchdog-calls-audit rather than competing with it. User Advocate's synthesis after Auditor's finding.
- **Builds on:** architect-frame-log, advocate-audit-trail-hybrid

### 8. Refuse start if source hash changed without algo_ver bump
*high feasibility* — argued by: Brainstormer

Hash each engine stage module at import time; store alongside declared algo_ver. If code hash changed but version string didn't, runlog refuses to start. Determinism-by-construction, not by developer discipline.
- **Why it's non-obvious:** Breaks the assumption that determinism guarantees are self-enforcing. The classic diagnosis-doc failure mode is an unannounced constant tweak — this makes that class of bug impossible to ship.
- **Grounding:** runlog.py exists as the start gate; algo_ver already tracked. Ten lines of hashlib on module.__file__ contents.

### 13. Add regime distribution query to quality.audit() to explain setup silence
*high feasibility* — argued by: Auditor

One SQL against existing regime facts — how many universe symbols are currently in RANGE vs TREND vs TRANSITION — surfaced in the audit output. When NO_ELIGIBLE_PLAYBOOK dominates rejections, the operator immediately knows whether it's market-driven (most symbols ranging) or engine-broken.
- **Why it's non-obvious:** Breaks the assumption that setup rejection volume is a pipeline signal. setups.py:playbook() returns None for RANGE unconditionally; the 4076 rejections are almost certainly correct behavior, but indistinguishable from a broken engine without regime visibility.
- **Grounding:** regime.py emits regime facts to the store on every classification change; store.get_facts() exists; quality.py already queries the store extensively. Zero new infrastructure — one GROUP BY query added to the audit.

Every stage writes one row with input/output hashes and the rung outcome. Operator can answer postmortem questions like 'what was missed during the 03:47 outage?' without building a shadow engine or replay infrastructure.
- **Why it's non-obvious:** Breaks the assumption that audit trail must be comprehensive replay infrastructure. Hashes provide diagnostic power without replay overhead.
- **Grounding:** SQLite is already in WAL mode; one prepared statement per stage, one column addition to runlog or new table.
- **Builds on:** watchdog-calls-audit

### 15. Dumb-twin assertion pairs writing to a divergence_log, auto-disable after K cons
*medium feasibility* — argued by: Architect

Each stage carries a five-line naive twin (dumb swing detector next to the real one). The twin does not gate — it writes divergence to frame_log. When a symbol accumulates K consecutive bars of over-threshold divergence, that stage's setup type auto-disables for that symbol until N clean bars restore trust. Catches sudden break AND slow rot on the same pipe, no freeze.
- **Why it's non-obvious:** Breaks Brainstormer's original assertion-pair (which raised and reintroduced the freeze problem I'd just talked Contrarian out of). K-bar consecutive threshold means one-bar noise never triggers; ten-in-a-row on BTC is cardiac.
- **Grounding:** Determinism claim in README makes twin-vs-real diffing meaningful; auto-disable is Brainstormer's #10, storage is my frame_log — the parts exist, the composition is new.
- **Builds on:** assertion-pair, confidence-gated-feature-flags
